## 3. 发现与处理

### F1｜来源表述带有内部语境（中风险，已修复）

原文多处使用“用户确认的工程阅读工作台”“确认过的工作台布局”等表述。虽然没有出现公司、产品或项目名称，但在公开仓库里会不必要地暗示某个内部来源。

处理：在发布副本中改为“经脱敏的工程阅读工作台布局基线”“脱敏后的通用虚构模板”，保留“脱敏”事实，去掉对话和内部确认语境。

涉及文件：

- `SKILL.md`
- `references/reading-design.md`
- `references/portability.md`

### F2｜项目地址出现在文档中（低风险，保留）

`README.md` 和 `docs/wechat-article.md` 包含 `https://github.com/AGouzi/rtl-reading-web`。这是项目自身的公开地址，属于预期内容，不是隐藏外链或遥测。

### F3｜布局基线的业务归属（残留风险，需发布者确认）

参考页保留了工作台形态、三栏比例、七页签和交互语言。当前包内没有任何真实名称、数据或源码，但如果这套布局本身被所在组织视为保密设计资产，公开前仍应取得相应授权。

这不是技术泄密，而是**业务保密边界**。建议发布者在点击“Public”前自行确认一次。

### F4｜许可证与代码归属（低风险，需发布者确认）

仓库使用 MIT License，版权行写为 `rtl-reading-web contributors`，未使用个人或公司名称。发布者应确认自己有权以 MIT 方式授权这份技能及其参考实现。
