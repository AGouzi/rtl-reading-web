# 页面与信息设计

用以下契约约束内容和交互。它规定信息应发挥什么作用，并规定默认模板的首屏结构；没有用户指定的替代风格时，工程差异只改变事实，不改变阅读密度和基本层级。

必须查看 [内置离线网页](../assets/reference-reader/index.html) 及其 `style.css`、`data.js`、`app.js`。该网页是脱敏后的通用虚构模板；只复用工作台结构、视觉与交互，工程内容仍从本次输入建立。不要把它当作“灵感来源”后重新设计，也不要退化成简单单页 demo。

## 1. 读者的主路径

默认按“它做什么 → 请求怎么走 → 关键条件是什么 → 代码在哪里”组织。

| 阅读层 | 默认回答的问题 | 合适的呈现 |
| --- | --- | --- |
| 总览 | 模块接收什么、完成什么、输出什么？ | 一句具体任务 + 一张必要的结构/通路图 |
| 职责 | 哪个模块负责哪一步？接口如何相连？ | 按事务顺序排列的模块和关键接口 |
| 行为 | 一笔请求何时被接受、等待、完成或失败？ | 有条件的步骤、时序或状态转换 |
| 实现 | 哪段 RTL 决定这个行为？信号怎样变化？ | 源码、语义详情与真实跳转 |
| 依据 | 这个结论来自哪里？验证到什么范围？ | 就近来源入口 + 可展开的报告信息 |

简单设计可以合并这些层。数据通路与控制通路只有在回答不同问题时才分开。没有实际价值的独立章节不创建。

总览页从上到下按：具体任务、3 个下一步入口、主结构图、验证摘要或来源折叠区。入口顺序与后续阅读顺序一致。左侧负责模块/信号/文件定位，中央承载当前阅读页，右侧显示当前模块或信号的细节。

“下一步”应描述目的，如“跟踪一次写请求”“查看应答状态机”，避免一屏出现大量同等突出的跳转按钮。默认只保留当前阅读路径需要的主要动作。

### 1.1 默认视觉与首屏契约

| 检查项 | 默认值 | 不合规示例 |
| --- | --- | --- |
| 顶栏 | `56px`，品牌 + 7 个页签 + 主题切换 | 只在正文顶部放导航，或把页签改成普通段落标题 |
| 左栏 | `250px`，模块树 + 信号搜索 + 源码文件 | 只放 3 个阅读链接，丢掉全量信号和文件定位 |
| 中央 | 当前页签的完整阅读工作区 | 把全部内容排成一条超长滚动文章 |
| 总览首屏 | H1 + 一句 lead + 3 个阅读入口 + 1 张结构图 | 4 个统计卡、重复信号墙、多个同等级大图 |
| 右栏 | `360px`，当前模块/信号上下文 | 永久空白或把中央内容再复制一遍 |
| 底栏 | 当前页签面包屑 + 简短操作提示 | 用底栏解释业务规则 |

七页签的职责：

| 页签 | 回答的问题 |
| --- | --- |
| 总览 | 模块做什么，先读什么，整体请求怎样穿过系统 |
| 模块结构 | 层级、实例、职责和端口怎样连接 |
| 数据流 | 一笔真实数据或请求何时被接收、处理、等待和完成 |
| 控制流 | 状态、有效位、ready、优先级和错误出口怎样推进 |
| 代码导航 | 哪个文件与行号决定当前行为，信号落在哪里 |
| 时序波形 | 有真实波形时，关键握手在哪些采样点成立 |
| 仿真验证 | 哪些场景真实执行过，哪些边界没有覆盖 |

没有证据的页签不得编造；可以省略该页签，或在页内给出“当前快照没有对应波形/报告”的具体原因。

桌面使用 `250px / minmax(0,1fr) / 360px`，`1400px` 时变为 `220px / 1fr / 330px`，`1180px` 以下右栏变抽屉，`860px` 以下左栏也变抽屉。首屏在 `1440×900` 下应同时看到顶栏、左侧定位、H1、3 个阅读入口及主结构图的大部分。

## 2. 信息密度与文案

- 开头一句话交代具体行为，避免“这是一个功能强大、设计完善的模块”等评价。
- 每个区块只承担一个问题。标题与首句不能同义复述。
- 同一事实只保留一个主要呈现位置，其他地方用链接引用。删除重复模块清单、重复文件清单和没有决策价值的总数。
- 折叠完整分支、参数表、协议字段表、来源记录等次级资料；折叠摘要用真实内容提示，如“复位与更新细节”“代码依据 · 3 处”。
- 没有实质内容的分区省略。未知事项给具体原因，不堆满“暂无/待完善”。
- 不用静态口号、教程式界面说明和大量“已确认”标签制造信息量。能通过按钮文案与布局表达的操作，不再写一段使用说明。
- 不为所有信号重复解释常识。对当前设计的特殊语义、约束、反压和优先级给足信息。
- 总览不引入装饰性统计卡；验证数字只放在验证页或总览底部的一条真实摘要中。
- 左栏已提供全量信号搜索时，中央只放当前主路径需要的少量信号入口；右栏详情与中央用途不能重复展开。

坏例：`信号功能说明 → 功能说明 → 这是一个标志位，用于表示模块状态。`

好例：`route_active → 标记已接受请求的载荷路由仍在占用，门控后续载荷的 ready。`

后者只是写作示例；真实用途必须从实际驱动与使用位置确认。

## 3. 对象的内容契约

### 模块

优先显示模块名、一句职责、关键入口/出口，以及可用的源码动作。层级、参数、完整端口表按需查看。端口优先按 AXI、AXI-Stream、自定义总线、时钟复位等协议/用途分组，识别不了再按方向分组；完整表默认折叠，不把上百个端口等权铺满首屏。IN/OUT 可用低饱和方向底色，协议组标题另用分组底色；颜色只辅助扫读，不能替代方向文字、真实端口名和组标题。

“无状态机”“只做组合逻辑”“无跨时钟”等结论也需要完整检查，不能因为没有找到 `state` 这个变量就得出。

### 模块内部图：输入 → 处理 → 输出

模块结构页先给一张顶层连接图；选中子模块后，中央图就地换成该模块的内部图，并保留返回顶层的入口。内部图按数据、控制、状态三条带组织，至少让读者看清：

- 数据从哪里进入、经过哪个缓存或重排单元、从哪里输出。
- 哪个状态机、计数器或握手条件在推进这条数据通路。
- 哪个 MUX 在选源、选槽或选 Bank，选择条件是什么。
- 哪条路径是错误、超时、丢弃或恢复，和正常路径分开。

缓存画成带 Bank 标记的存储块，选择器画成梯形，状态机用圆角块并写出状态名，计数器标出 `+1`。节点标题用源码里的真实信号或单元名。顶层主图只在悬停和点击详情中展示真实条件与成员信号，不在框内或线旁铺开；内部图若必须放简短标签，也要避让节点和端口。每个节点能打开信号详情，`L` 行号能定位源码。叶子模块没有内部通路时直接说明，不为凑图硬造 FIFO、仲裁器或状态机。

结构图先闭合模块边界：接口在数据模型中由真实端口族闭合，顶层摘要用功能语言写清“输入什么、做了什么、输出什么”，真实端口族在悬停或详情中展开；中间只放本次代码存在的缓存、重排、MUX、状态或错误对象，每条输出都要能落到下游输入。同一端口族只在语义和流向一致时合并；数据、错误、控制等不同流向使用独立引脚。摘要、主图与详情使用同一组事实，不靠概念名或行为结论补空白。

结构图只画结构和对象，不画行为结论：实例、端口、BRAM/FIFO、MUX、状态寄存器、计数器、错误端口可以入图；状态名可以写在 FSM 节点里，但“单拍脉冲”“不阻塞正常帧”“握手后进入某状态”等结论应放到数据流、控制流或信号详情。分带标题也用真实对象或信号族命名，例如“控制与存储 · state / slot_busy / ev FIFO”，不要用一整句行为说明代替。

### 连线

每条有效边至少关联一组实际信号或端口映射，并有一个可点开的源码依据。阶段名（如“请求”“完成”）只能作为边标题，不能代替信号名；成员信号放在点击详情和边清单中，主画布默认不铺，避免挤压节点和流向。总线可以聚合成一条边，但展开后必须能看到成员信号。边点击后显示方向、信号、端口映射或赋值依据，不把没有源码来源的关系画成确定连接。

顶层图和内部图的边必须先由实例端口映射、赋值关系或明确的代码条件生成，再做布局；不能先手写坐标再补文案。每个可见模块的输入和输出都应在图上成对出现，图上出现的端口/网名必须来自本次 RTL；概念名只能作为副标题或边标题，不能替代真实标识符。顶层图至少覆盖请求描述符、载荷流、响应流和错误流，不能只画控制分支。

布图先按主流程分列、按分支分上下泳道：同级模块基线对齐，模块框紧凑包住标题与职责，外部接口与所连接引脚对齐。不要用大面积空白撑开图，也不要为了视觉错线把端点从引脚上平移。连线从节点边界正交出入，不能穿过非端点节点；同一节点同侧有多条边时分散锚点，不能共用同一端点后互相覆盖。

所有连线的首点和尾点必须等于真实引脚锚点。需要分流时，先用一条可见 trunk 连到 junction，再从 junction 展开各分支；双向总线用一条两端带箭头的线，不拆成两根端点偏移的平行线。标签优先贴近连线，但必须避让节点、端口文字和其他标签；空间不足时进入独立标签轨道，宁可与连线略有距离，也不能压住图上的文字。

### 事务/流程

每步交代触发条件、执行动作、等待条件和下一步；有真实错误出口时给出。区分描述符被接受、载荷被接受、执行完成、响应发送完成。不得把这些阶段笼统写成“请求完成”。

优先选择贯穿主要模块的一条真实事务。读写或异常行为确有差别时再补分支，不把所有 `always` 块画成平行流程。

选中一步时，同步高亮涉及的模块、关键信号和源码行；当前步骤的完整说明只保留一个主要位置，右栏显示当前模块/信号，不重复整段步骤全文。静态逻辑推演与 VCD/仿真观测必须明确区分。

### 状态机与存储

有真实状态机时，展示状态名、转换条件、动作以及复位/错误分支；状态名只用于命名，转换必须来自 `case`、`if` 或等价代码。没有可追溯状态机时说明不适用，不生成空状态图。

有 FIFO、RAM、数组或双 Bank 时，展示容量/位宽、读写条件、数据来源与去向、有效与释放条件。容量和位宽来自声明与参数，不能求值时保留表达式。BRAM 是综合映射结果，不凭数组名或容量猜测；没有综合报告时写“存储结构/数组，可能映射为 BRAM”。

### 信号详情

默认阅读顺序：

1. 名称 + 所属模块/实例 + 方向或种类 + 位宽。
2. 可用动作：定位代码；有匹配数据时查看波形。
3. 一句具体用途；一条主要更新/生效条件。
4. 可展开细节：复位与完整更新规则、来源与影响、代码依据。

展开后必须有信息增量。详细说明见 [RTL 语义与证据](rtl-evidence.md)。展示当前波形值时保留信号上下文和采样时刻，不用原始值替代用途。

### 常量

`localparam`、`parameter` 和状态编码这类名字是另一类可查对象。它们在编译期取值，没有时钟沿、复位值或保持路径。详情按“作用 → 取值 → 上级覆盖 → 声明位置 → 引用位置”组织，套用信号的句式会误导读者。

- 源码中与信号同样可点击，并用颜色或虚线下划线区分，避免把常量当成会变化的信号。
- 左栏索引单列一组常量，参数和状态编码都能搜到，名称重复时带上所属模块。
- 点击后给出取值、声明文件与行号、引用位置；没有引用就写明只在声明处出现。
- `parameter` 必须说明哪些上级实例例化了本模块、是否在 `#(...)` 中覆盖、覆盖表达式以及实际采用默认值还是上级传值；`localparam` 明确写明不能被上级覆盖。中文用途优先取声明行或上级同名参数注释，取不到就说明缺失，不编通用解释。
- 覆盖表达式按源码原样展示；没有可靠常量求值器时，不做位宽截断或“实际数值”推断。

### 源码

保留原始标识符、源码内容、行号和文件上下文，支持定位高亮。把“阅读入口/关键片段”放在源码之前，解释放在相邻详情里。不要重复呈现多个同名文件标签。代码字体栈要同时覆盖等宽 ASCII 与 CJK 回退（如 Consolas + Noto Sans SC / 微软雅黑），注释保持正体，避免中文落回锐利默认字体或被浏览器合成斜体。

从信号或证据跳转后，目标行应进入可视区并短暂或持续高亮；目录同步对应模块/文件，用户仍可判断自己在什么位置。从模块树、结构图或上下文选中模块后，再进代码导航应打开该模块文件并定位模块起始行；显式信号/锚点证据行优先于模块默认位置。回到上一级时尽量保留阅读位置。

代码跳转只调整代码容器自身的滚动，不改变整页滚动位置；在常见桌面和窄屏下，目标行应位于代码可视区中部附近，而不是贴在最上方。无法居中的边界行允许自然吸附到容器顶部或底部。

从右栏详情发起的跳转只替换中央正文。右栏保持当前模块、信号或常量，直到读者主动选择另一个对象；跳一次代码就换成模块上下文，会让人丢掉正在读的对象。

### 验证与波形

已有可信报告才显示验证范围与记录，报告详情按需展开。没有报告就不生成通过徽标、测试数或覆盖率。波形不是必备章节，具体真实性要求见证据契约。

## 4. 交互视觉

| 元素 | 应呈现的信号 |
| --- | --- |
| 主要动作 | 明确按钮，动词或目的文案，足够对比度 |
| 次级跳转 | 链接或次级按钮，有下划线、箭头或边框等可见线索 |
| 可点击图节点/关系 | 明确的交互边界或跳转线索，hover 与键盘焦点反馈 |
| 静态标签/属性 | 中性文本、弱化底色或分隔，不使用与按钮相同的边框、填充和悬停效果 |
| 当前选择 | 使用统一选中态；不能只以颜色传达状态 |
| 不可用功能 | 隐藏，或禁用并给具体原因；不能点击后无反馈 |

图节点、表格行和页签只有确实可操作时才显示为可点击。用语义化 `button/a/details`；支持 Tab 和 Enter/Space，焦点可见。按钮的无障碍名称应说明动作对象，不能都叫“查看”。

同类动作在全页只使用一种视觉组件：目的相同的“查看信号”统一为文字动作或统一样式的按钮；同一层级源码入口统一尺寸和边框。不要给输入、输出、配置各造一套标签按钮。静态属性与可操作项必须从默认状态就能区分。

同名信号选择器显示模块/实例以消除歧义；不能默默选择全局第一个匹配。选择、上下文与代码位置有同一个状态来源，避免侧栏选了 A 而主体讲 B。

## 5. 布局与适配

- 正文行距与宽度优先服务阅读，代码等宽；不靠过小字号塞下内容。
- 桌面保持工作台式三栏；`1180px` 以下把右侧改为抽屉，`860px` 以下把左侧也改为抽屉，主阅读顺序保持不变。
- 抽屉有明确关闭入口，支持 Escape、焦点进入/约束/返回；从详情跳到代码时关闭遮住目标的面板。
- 整页不横向溢出。代码、表格和大图可在自己的容器内横向滚动。
- 图中入口、出口与主要方向清楚。文字不能被连线遮挡，长标识符可换行或局部滚动；颜色有文字或线型辅助。
- 动画仅用于解释状态或跳转反馈；尊重减少动态效果设置。主题切换按需提供，不是页面必须有的功能。

## 6. 每个元素的删留检查

逐个问：它帮助用户定位对象、解释行为、追溯依据，还是决定下一步？如果移除后理解与操作没有损失，就删除或合并。来源、验证边界与不确定性有独立价值，但可放在不打断主阅读的位置。
