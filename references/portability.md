# 迁移与分享

## 安装和使用

把完整的 `rtl-reading-web/` 目录放进接收方 AI 工具支持的技能目录，保持 `SKILL.md` 在该目录第一层，保留 `agents/`、`references/` 和 `assets/`。不需要原作者工程或聊天记录。

- 支持项目级 `.agents/skills/` 的宿主：放在 `<目标项目>/.agents/skills/rtl-reading-web/`。
- 其他宿主：使用该宿主指定的个人技能目录，不写死用户名、盘符或操作系统路径。
- 支持 `$skill-name` 的宿主可用 `$rtl-reading-web` 调用；其他支持 Markdown 技能的工具可直接读取 `SKILL.md`，并按其相对链接继续读取资源。
- 调用时提供接收方自己的源码、顶层和输出目录。没有参考网页时使用内置资产。示例输入统一用占位路径，不携带任何真实工程地址。
- 直接用浏览器打开 `assets/reference-reader/index.html` 可查看离线参考；该页面不发起网络请求，仅用浏览器本地存储记住主题选择，也不依赖安装时的位置。

## 内置参考的使用边界

参考页演示“功能 → 条件 → 信号 → 源码”的阅读方式，采用从零创作的通用示例。它与确认过的工作台布局同构，但不是某个产品的源码副本，也不是经过仿真的硬件 IP。

可以复用布局、颜色、通用组件和交互实现；本次工程事实全部重新建立。参考页的七页签是工作台入口，不代表每个工程都必须填满七页；没有真实波形或验证报告时按规则省略或显示空状态。

普通代码阅读任务仍需保留用户输入的真实标识符与源码以确保可追溯。制作可公开分享的技能包或示例时，才应用下列分享边界；不能把正常工程页面偷偷替换成虚构实现。

## 参考资产与转发包的脱敏规则

1. **从零构造示例。** 使用通用虚构模块、信号和短小 RTL。不要仅重命名真实工程后保留其特有架构、协议、寄存器映射、地址、时序指标或错误路径。
2. **仅保留通用设计语言。** 保留阅读顺序、间距、颜色、交互区分等 UI 规则。包内不得出现真实项目/客户/公司/人员名、型号、内部路径、主机名、网络地址、账号、密钥、仓库地址或专有协议字段。
3. **不携带真实材料。** 不打包真实源码快照、波形、验证报告、截图、工具日志、内部文档、版本历史或其哈希。示例哈希只对应包内虚构 HDL。
4. **检查隐藏内容。** 同时检查 HTML 注释、JS 数据、JSON 清单、CSS URL、SVG 元数据、source map、压缩包条目和符号链接。页面肉眼看不到的内容也属于分享内容。
5. **资源全部自包含。** 仅使用相对路径引用包内资源；不链接作者机器、私有网页或临时预览服务。字体使用系统回退，禁止遥测、分析脚本和隐式外网依赖。
6. **限制打包范围。** 只打包技能目录中审核过的文件，排除 `.git`、缓存、备份、环境文件和测试临时产物；不能把上级工程目录一起压缩。

## 迁移验收

- 将待发布包复制或解压到一个不同位置，仅以新目录中的文件检查相对链接和资产存在性。
- 检查全部文本严格 UTF-8 无 BOM，引用路径无盘符、家目录、原作者目录或外部资源依赖。
- 核对参考页的内嵌源码行号、文件跳转和五个相对资源（`index.html`、`style.css`、`data.js`、`semantics.js`、`app.js`）完整可用。
- 以承诺的打开方式测试参考页。依赖相对脚本且没有 fetch/模块加载时可双击打开；若验证工具限制本地 URL，明确记录限制，不能冒充已通过。
- 审阅参考内容确实来自合成示例；关键词扫描只能发现已知名称，不能独立证明业务内容已脱敏。
