# RTL 语义与证据

页面说明的是本次读取的源码版本。旧网页只可作为布局参考；注释、文档、信号名称和正则结果是线索，不自动成为实现事实。

## 1. 一份快照与稳定身份

- 保存轻量 `source-manifest.json`：顶层、实际参数/宏配置、文件逻辑路径与 SHA-256、生成时间。无需引入数据库。
- 展示的源码、行号、模块层级、端口映射、信号说明和图均绑定该快照。源码更新后重新检查依赖和结论，不只替换文字或局部行号。
- 使用“文件 + 模块 + 信号”识别声明；层级行为和波形使用“实例路径 + 信号”。同名信号、不同参数实例和不同位选不能混为一项。
- 位宽/方向/符号性来自声明与有效参数：无范围标量声明为 `1 bit`，参数化范围先展开 `localparam/parameter` 再计算；不得从赋值右侧、操作码字面量、相邻信号或总线宽度推断。数组/存储把名称前的 packed 范围解析为元素位宽，把名称后的 unpacked 范围单独解析为深度，不能把深度乘进位宽；`(* ram_style = "block" *)` 等属性前缀不得遮蔽声明。无法求值时保留表达式并说明未解析，不编一个数值。
- 代码依据按 `file:line` 去重；同一位置的多条说明合并，保留最完整的一条。每条依据应可复制 `file:line` 并跳转到源码行。
- 外部 IP、未给出的 include、复杂宏或 generate 等形成的边界要明确列出；不能画出没有来源的内部连接。

内部模型可以简化为下列结构，具体文件布局自由：

```json
{
  "id": "top.u_rx.payload_valid",
  "file": "rtl/rx.sv",
  "module": "rx",
  "name": "payload_valid",
  "width": 1,
  "purpose": "具体用途，由驱动与使用位置共同确认",
  "evidence": [
    {"claim": "reset", "file": "rtl/rx.sv", "start": 40, "end": 43},
    {"claim": "update", "file": "rtl/rx.sv", "start": 44, "end": 54}
  ]
}
```

这是字段示例，不是可直接展示的工程事实。结构化数据应转义后渲染，源码/注释不能作为 HTML 执行。

### 1.1 连线、模块边界与存储资源

连线是实例端口映射或赋值关系的聚合，不代表每一拍都发生传输。每条有效边至少保存实际信号/端口映射和一个可点开的源码依据：

```json
{
  "id": "u_ingress_to_u_router",
  "from": "u_ingress",
  "to": "u_router",
  "kind": "data",
  "signals": ["ingress_valid", "ingress_ready", "request_error"],
  "evidence": [
    {"file": "rtl/top.sv", "start": 30, "end": 32, "note": "实例端口映射"}
  ]
}
```

阶段名（如“请求”“完成”）只能作为边标题，不能代替信号名。总线可以聚合成一条边，但展开后必须能看到成员信号。模块节点应支持下钻到内部实例、功能单元和端口；端口优先按 AXI、AXI-Stream、自定义总线、时钟复位等协议/用途分组，完整表默认折叠。没有子模块、状态机或存储时写明“不适用/未识别”及依据，不为凑视图生成空图。

存储资源检查 FIFO、RAM、数组或双 Bank 的容量/位宽、读写条件、数据来源与去向、有效与释放条件。容量和位宽来自声明与有效参数，必须分别保留元素位宽和深度，例如 `reg [63:0] mem [0:SLOT_COUNT*WORDS_PER_SLOT-1]` 是 `64 bit × 8 项`；不能求值时保留表达式。BRAM 是综合映射结果，不能凭数组名、`ram_style` 属性或容量猜测；没有综合报告时只写“存储结构/数组，可能映射为 BRAM”。

### 1.2 并发、依赖与结构图边

画结构图前先做一遍“驱动者扫描”，至少记录下列事实：

| 对象 | 更新/写使能 | 同拍数据源 | 同拍并行对象 | 后续消费者 | 源码依据 |
| --- | --- | --- | --- | --- | --- |
| 存储、FIFO、寄存器、输出端口 | 哪个表达式真正推进它 | 当前拍从哪里取样 | 同一拍还更新谁 | 谁读取或握手 | `file:line` |

判定规则：

- `B` 的更新表达式或输出选择实际使用了 `A` 的结果，才存在 `A → B` 的依赖边。
- 同一拍有效/接收条件同时更新 `A` 和 `B`，且两者互不读取对方结果时，`A`、`B` 是同一 source 的并行消费者，应从共同 source 或可见 junction 展开，不能串成 `A → B → C`。
- 校验/状态节点的结果如果没有进入存储写使能，就不能画成“校验器 → 存储”的串行数据边；它可能只控制事件提交、清槽或错误脉冲，应画成独立的控制/状态边。
- 协议接口必须按端口归属放置。模块没有声明 `m_axi_*` 时，AXI-Lite 只能是外部边界或另一个拥有该端口的模块节点。

一个最小判定例子：`mem_wr_en` 由接收拍有效和接收状态控制，`mem_wr_data` 直接从当前拍输入取样；同时 `crc_next` 也由当前拍输入和有效字节数更新。此时 `mem` 与 `crc` 是并列节点；只有 `tlast` 终检结果进入事件压栈条件时，才有“终检 → 事件提交”的控制边，而不是“CRC → mem”的数据边。

## 2. 每个重点信号要回答的问题

| 维度 | 要检查的实际 RTL | 解释要求 |
| --- | --- | --- |
| 用途 | 声明、驱动、消费者 | 它保存什么或门控什么，影响哪个具体行为 |
| 生效时机 | 敏感表、条件、组合表达式 | 时钟沿/组合变化、使能、实际接收事件 |
| 复位 | reset 分支与初始化 | 同步/异步、极性、值及其优先级；未复位就如实写明 |
| 更新 | 完整赋值分支 | 置位、清零、计数、覆盖、保持；不能漏掉更高优先级条件 |
| 来源 | RHS、实例端口、选择条件 | 区分数据输入与条件控制，解释必要的表达式 |
| 影响 | 使用位置 | 决定哪个 ready/valid、状态、数据、地址或错误路径 |

不要求每个临时线网都写成长文，但顶层接口、主事务握手、关键状态/计数和用户点选的信号不能用通用模板假装已解释。未解释项给具体状态，并仍允许查看源码。

## 3. 容易误读的语义

- `valid && ready` 才是当前接口接受一次传输的事件；只有 RTL/协议证据明确时才把 `last` 与该事件组合成结束条件。检查背压期间的保持、缓冲和丢弃规则。
- `if/else if` 的先后、同一过程多次非阻塞赋值的覆盖、默认赋值与后续赋值的优先级必须纳入解释。非阻塞赋值右值通常取本次时钟沿更新前的值。
- 跨过程驱动不能用文本顺序解释优先级。组合逻辑、锁存行为与寄存器保持不能互相套用；`wire` 并不自动说明所有行为无状态。
- 状态机检查状态寄存器、下一状态与输出条件。状态名称只能帮助命名，转换条件必须来自代码。计数器检查起始值、终止比较、位宽截断及溢出。
- 实例连接沿端口映射与赋值表达式追踪。声明方向不等于整个工程的数据方向；数据依赖与条件依赖分别说明，不堆没有解释的信号名单。
- 时钟域与复位域仅按已检查内容描述；阅读代码不能替代 CDC、时序或硬件验证。对黑盒和未读范围不下完整性结论。

### 写作示例：不要只按名字解释

以下是独立演示片段：

```verilog
always @(posedge clk) begin
  if (!rst_n)
    route_active <= 1'b0;
  else if (req_valid && req_ready)
    route_active <= 1'b1;
  else if (payload_valid && payload_ready && payload_last)
    route_active <= 1'b0;
end
assign payload_ready = route_active && sink_ready;
```

不合格：`route_active 是控制/状态标志，控制流程的启动、保持或结束。`

合格默认说明：`标记已接收请求的载荷路由仍在占用；为 0 时阻止载荷被继续接收。请求握手置位，尾拍握手清零。`

展开细节：`clk 上升沿更新，低有效同步复位清零。请求握手优先于尾拍清零；同拍发生时保持为 1，其余情况保持。payload_ready 还要求 sink_ready。`

依据分别关联 reset、两个更新分支与 ready 表达式。实际工程的优先级可能不同，不能复制此例作为结论。

## 4. 三类结论与来源

1. **源码事实**：可直接追溯到声明、表达式、分支、状态转换或实例连接。
2. **设计推导**：基于事实解释目的或影响。没有设计文档时不把“为了优化时序/吞吐”写成设计者意图。
3. **仿真观测**：来自指定用例、配置和波形时刻；只能覆盖观察范围。

关键用途、更新规则、握手与图中连接需有可点开的依据，跳转到实际文件与行号并高亮。相邻多条结论可共用一个依据入口，不为每句堆一排徽标。范围未知就标具体边界，不使用没有依据的百分比置信度。

源码与注释/文档冲突时，以实现事实讲当前行为，简短记录冲突；这不授权顺手修 RTL。无法确认时保留未知，不伪造最终结论。

## 5. 波形与验证记录（仅有数据时）

- VCD/其他波形匹配实例路径、位宽和版本，保留 X/Z；找不到时隐藏/禁用对应动作，并说明具体原因。
- 有 VCD 时用完整查看器展示分组信号树、场景、时间游标、缩放/适配、播放、当前采样和变化事件。只画 5 行静态波形不算实现波形页。
- 显示数据源、仿真器、时间精度、生成时间、时间窗口、游标时刻及采样口径。文件不能确定边沿前后或 delta 周期时，不宣称精确证明了更新顺序。
- 总线可以按 `bitSplit` 展开成真实位线；每一位都从该总线的 VCD 采样中读取。不得把 hex 总线保留为唯一视图，也不得用推导值或随机值补成位线。
- 状态名只来自源码编码或显式 `stateMaps`；找不到映射时保留数值。场景窗口、分组和显示格式属于阅读配置，不改变 VCD 事实。
- 波形信号详情显示路径、作用域、位宽、当前采样值和源码入口；无源码映射时明确说明，只保留 VCD 事实。
- 示意时序必须标“示意”，不得标“实测/VCD”。禁止用随机值、推导值填充貌似真实的采样表。
- 用例数、通过率、覆盖率只来自可读报告，附报告路径、日期/版本和适用范围。旧报告不能自动证明当前快照；生成时间不能冒充验证时间。
- 没有测试数据时仍可交付有用的代码阅读页，明确“本次未运行仿真”。不要为补齐网页无故运行昂贵 EDA 流程。
