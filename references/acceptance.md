# 验收标准

按实际规模选择必要检查，并记录真实结果。下列是结果要求，不要求为静态文案建立单元测试，也不要求启动 RTL 仿真。

## A. 语义与来源

| 检查 | 通过条件 |
| --- | --- |
| 快照一致性 | 清单哈希、页面源码、行号与本次输入一致；不把旧网页内嵌代码当作当前 RTL |
| 范围明确 | 顶层、参数/宏和未解析依赖可查；同名信号按模块/实例区分 |
| 参数覆盖 | `parameter` 详情说明作用、上级实例、覆盖表达式和实际采用值；`localparam` 明确不可覆盖；没有可靠求值器时不伪造“实际数值” |
| 信号具体 | 设计中存在的关键握手、主要状态与清零/保持信号均能解释具体行为；纯组合模块检查输入依赖与输出条件，不虚构状态 |
| 优先级 | 存在多分支或同拍事件时，选择对应过程核对复位、更新、覆盖和保持；不适用项省略 |
| 事务贯通 | 有事务时可从接受到结果输出逐步跟踪，等待和完成条件有代码依据；纯组合模块改为跟踪输入到输出的表达式链 |
| 连线可追溯 | 每条有效边在数据模型中至少关联实际信号/端口映射与源码依据；总线可展开到成员信号；阶段名没有替代信号名；顶层图覆盖子模块成对的输入/输出，不出现无接收端的输出；真实成员信号可在右栏查看，顶层主画布默认不铺 |
| 导线与标签 | 连线从节点边界出入且不穿过非端点节点；同侧多边锚点分散；标签不与节点、端口或其他标签重叠，放不下时进入独立标签轨道 |
| 模块下钻 | 模块节点能进入内部实例、功能单元和端口分组；面包屑/返回保留上下文；无子模块时边界明确 |
| 状态机/存储边界 | 主路径有状态机时核对状态、转换、复位/错误分支；有 FIFO/RAM 时核对容量、读写和释放条件；无则标记不适用；BRAM 需综合证据 |
| 结论分级 | 推导、观测和源码事实不混淆；无波形/报告时不出现伪造的实测值与通过记录 |

小设计逐项检查全部重点对象；大设计覆盖主路径、分支与用户指定对象，并在交付中说明实际检查范围。抽样不等于全库语义验证。

## B. 阅读体验

- 首屏能看到具体任务和明确的继续阅读入口，信息按左到右、上到下推进。
- 未指定其他风格时，首屏骨架与内置参考页一致：`56px` 品牌顶栏与七页签、`250px` 左栏、中央总览、`360px` 右栏和底部状态栏都在。
- 中央依次为任务、3 个阅读入口和 1 张主图；没有装饰性统计卡，没有把侧栏信号或右栏详情复制成中央信号卡墙。
- 同一块没有“信号功能说明 / 功能说明”这类重复；展开项含独立信息，无空面板或通用占位解释。
- 同类可操作控件全页使用一致样式；静态属性与按钮/链接在默认状态即可区分，hover 之外也有线索。
- 从模块、流程、信号或依据进入代码后，能看到正确文件、目标行和高亮，上下文同步；目标行在代码容器内垂直居中，边界行可自然贴边但不带走整页滚动。
- 选中模块后切到代码导航，文件与模块一致并定位模块起始行；之后显式点击信号、常量引用或锚点时，以证据行为准，不被模块默认位置覆盖。
- 常量（`localparam` / `parameter` / 状态编码）在源码和左栏索引中都能点击；详情给出取值、声明位置和引用位置，不写成会随时钟变化的信号。`parameter` 还要显示上级实例、覆盖表达式与默认/覆盖采用结论；`localparam` 写明不可覆盖。
- 代码区中文注释清晰可读，正体显示；字体栈含 CJK 回退，不出现锐利回退字形或浏览器合成斜体。
- 从右栏详情点“定位源码”、证据行或相关对象后，右栏仍停在原对象；只有主动选择新对象才替换。
- 图的标识符、端口与连线可读，箭头/图例表达明确；没有错误指向和无来源连接。
- 每条连线首尾坐标与真实引脚锚点一致；不同语义/流向不共用图钉，分流先到可见 junction 再展开；双向总线为单线双箭头；没有悬空、近似连接、反向绕回或穿过非端点模块的线。
- 顶层布局按主流程分列、按分支分泳道；同级模块基线对齐，模块框紧凑，外部接口与相连引脚对齐；没有大面积空白或靠端点偏移制造的伪分离。
- 模块结构页能从顶层图下钻到子模块内部图；内部图至少区分数据、控制/存储、错误端口，并画出真实存在的缓存、选择器或状态机。
- 结构图只画对象和连接；状态名可出现在 FSM 节点，行为结论放在数据流/控制流/信号详情，不用“单拍脉冲”等行为句当分带标题。
- 真实端口/信号名必须出现在悬停、连线详情或边清单中；顶层主图框内只保留实例名和一句职责，实例上方的 IN/DO/OUT 摘要用功能语言，不铺端口族或成员网名，且入口与出口成对闭合。
- 顶层连线点击后在右栏展开成员网名、端口映射、门控条件与源码依据，且仍停在顶层图；内部图节点点击后仍停在当前模块页；信号节点打开详情，`L` 行号打开对应源码，详情不指向不存在的信号。
- 端口按协议/用途分组，完整端口表默认折叠；IN/OUT 有可区分但克制的方向底色，组标题有独立底色；颜色不替代方向文字和真实端口名。右栏只保留分组摘要，不重复中央完整表。
- 事务步骤选中后模块、信号和源码高亮同步；步骤详情只有一个主要位置，右栏不重复整段步骤全文。
- 用户无需为理解一句用途先展开多个面板；也不需要在每页重复读同一段说明。

## C. 浏览器与可运行性

实际打开生成页面，至少走通：主入口 → 模块/流程 → 关键信号 → 源码定位；有波形时再检查实际加载与定位。

1. 检查浏览器控制台、脚本语法与资源请求；没有新错误、失效链接或加载后空白。
2. 验证搜索、章节、展开/收起和选中同步；同名信号必须定位到正确模块/实例。空搜索和无结果状态正常。
3. 检查一个常见桌面宽度、约 1024px 和约 390px 窄屏；正文不横向溢出，大图/代码只在自身容器滚动。
4. 从代码页外跳转到一个中部行号，确认目标行进入代码容器约 50% 高度；再检查首行和末行不产生整页跳动。
5. 用键盘完成一次主要跳转；可见焦点，操作语义正确。存在抽屉时检查关闭、Escape、焦点返回与目标不被遮挡。
6. 若有主题切换，验证两个主题文字和连线均可读；没有主题切换则无需新增。
7. 按承诺的启动方式重新打开：声称双击可用则验证 `file://`；依赖 fetch/模块加载则使用本地 HTTP 并提供命令。
8. 保持文本 UTF-8 无 BOM，检查中文与原始源码无乱码；源码片段渲染为文本，不能执行其内容。

浏览器或工具不可用时，仍完成可行的结构/数据检查，明确哪些交互未验证。一次真实浏览器走查不能描述成自动化全覆盖测试。

## D. 交付前的删留与结束条件

逐块检查：是否解释一个新问题或提供必要操作？没有就删；是否把来源、限制删得无法核实？有就恢复到可展开的位置。

页面可运行、主要阅读链路贯通、关键语义与证据相符、没有已知阻断问题时完成交付。简要给出入口、运行方式、验证范围和实质限制；不为凑篇幅添加新的章节、仪表盘或无请求的功能。

## E. 默认参考页一致性

未指定其他视觉模板时，必须实际打开参考页与生成页对照，并记录以下结果：

| 检查 | 通过条件 |
| --- | --- |
| 首屏截图 | 两个页面在相同的桌面尺寸下具有相同的工作台形态、阅读顺序和信息密度；生成页允许内容和品牌不同，但不能退化成单页 demo 或普通长文章 |
| 三栏比例 | 宽屏接近 `250px / 自适应 / 360px`，并包含 `56px` 顶栏、七页签和 `26px` 底栏 |
| 首屏预算 | 总览阅读入口 3 个、主图 1 张、装饰性统计卡 0 个；验证摘要最多 1 条 |
| 页签行为 | 总览、模块结构、数据流、控制流、代码导航可走通；波形和验证只在有真实证据时提供 |
| 响应式 | `1180px` 以下详情抽屉、`860px` 以下目录抽屉；主阅读顺序不变，页面本身不横向溢出 |
| 重复内容 | 左栏、中央、右栏没有重复完整信号说明；全量信号只在一个主入口出现 |
| 控件语言 | 同类按钮、链接、图节点视觉一致；静态标签使用统一中性样式 |
| 次级信息 | 长规则、参数、来源和验证边界默认折叠，折叠摘要含真实内容 |
| 复杂度 | 如果生成页比参考页多出两类以上等权区块，必须逐块证明删掉会损失定位、理解或追溯 |

仅以“技术信息都正确”通过验收不合格。语义正确和参考风格一致需要分别通过。若用户明确要求另一种风格，则把本节的“与参考页一致”替换为“与用户指定页一致”，但首屏信息预算仍必须逐项核对。
